顺带说一个 RESTful 角度的问题
你之前问了 RESTful 风格。严格按 RESTful 来说，创建资源通常写成：

text
POST /api/appointment
而不是：

text
POST /api/appointment/create
因为“创建”这个动作已经由 POST 方法表达了，URL 里再写 /create 就有点“动作重复”。不过实际项目里，很多团队会在复杂业务中用 /create、/cancel 这类动作端点作为补充，这不算错，只是不完全符合纯 RESTful 风格。

api在这里的意思是接口，是后端提供数据给前端的一种方式，前端通过调用api来获取数据，然后进行展示。
